# Analyze proteomics

Use the bundled implementation rather than rewriting statistics. Reproduce the source notebook's procedures, with pairing determined by the user's experimental design rather than assumed.

## Workflow

1. Inventory input sheets/columns with `python scripts/run_proteomics.py --inspect /path/to/input.xlsx` (also supports parquet/CSV/TSV). For facility protein analyses use `facility_proteins` on `Summary` with `Raw_Intensities` sample columns; use `facility_peptides` on `Peptides (raw)` for peptide analyses, or another explicitly identified measurement sheet; never choose README, scores, spectral counts or IBAQ automatically. Inspect feature/sample orientation, intensity scale, gene annotations, organism, normalization already performed, biological versus technical replicates, requested subsets/contrasts, and pairing. Read [references/input-and-options.md](references/input-and-options.md).
2. Resolve scale (`linear` versus `log2`) explicitly. Require explicit pairing when preparing each contrast; use `paired: false` for independent biological samples. Never pair using row order or matching sample names. Ask when study design is unclear.
3. Create a JSON configuration from [references/example-config.json](references/example-config.json). Preserve notebook defaults unless overridden; record all choices. Use a fresh output directory. Relative paths resolve against the configuration's directory.
4. Use `scripts/proteomics.py` and `scripts/run_proteomics.py`. Install missing dependencies from `scripts/requirements.txt` in a task environment; InMoose may need a C/C++ compiler. Do not substitute ordinary regression for empirical-Bayes limma. Run `python scripts/run_proteomics.py --config analysis.json` with the actual absolute script path.
5. Read `run_summary.json`; only `status: complete` means the entire workflow succeeded. Inspect PCA, filtering, missingness, observed/imputed distributions, correlations, volcanoes, directional Hallmark tables and plots, and the hit-level imputation audit. Read [references/methods.md](references/methods.md) before interpreting results or changing methods.
6. Deliver configuration, calling script/notebook, CSVs, PDF/PNG figures, `methods.txt`, and `run_summary.json`. Use Library for user-facing analysis deliverables and preserve any existing repository workflow. Do not deliver synthetic validation outputs as biological results.

## Statistical guardrails

- For facility `Summary`, preserve `UNIPROT_AC`, `GENE_NAMES`, `FASTA_HEADERS`, `PROTEIN_DESCRIPTIONS`, `NUM_PRECURSORS`, `PROTEIN_WEIGHT` and `NUM_UNIQUE_PEPTIDES`. Select only `Raw_Intensities…` columns as raw measurements, strip that exact prefix to match metadata (preserving leading zeros), and allow explicit sample-name overrides. Never treat precursor counts, protein weights or peptide counts as sample intensities. Prefer these supplied protein abundances for protein-level analysis over deriving proteins from peptides.
- Preserve peptide/protein/site feature identity. For facility peptide sheets, retain `PEPTIDE_SEQ`, `PROTEIN_UNIPROT_AC`, `FASTA_HEADERS`, `GENE_NAMES`, and `PROTEIN_DESCRIPTIONS`; use metadata to choose raw sample columns and explicit mappings for different sample names. Keep peptide analyses labeled peptide-level. Never silently sum peptides, treat peptides as biological replicates, or infer phosphosites from peptide sequences. Ask before protein-level summarization.
- Preserve observed values and a separate missingness mask. Convert zero to missing only in linear-intensity inputs. Keep log2 zeros. Reject invalid intensities, duplicated identifiers, missing metadata samples, entirely missing samples and ambiguous pair mappings.
- Start all-sample PCA from the original full observed matrix. For every comparison, subset the original observed matrix first and independently normalize, filter, impute, select variable features, standardize and refit PCA. Never subset globally imputed values or concatenate comparison-filtered matrices to construct the all-sample PCA.
- Default filtering: >=4 observed values overall and >=1 per configured imputation group. Apply thresholds within the current scope and report feature exclusions. This does not imply four observations per group. Global imputation groups default to condition; configure tissue/condition strata when appropriate.
- Default KNN: three neighbors, uniform weights, nan-euclidean distance, feature rows as neighbors, fitted separately within each configured group. Keep imputation indicators separate from PCA/model input. Offer pooled KNN and Gaussian only as explicitly configured scenarios; never silently fill unresolved NAs by another method.
- Imputed t-test: two-sided equal-variance Student's t-test for unpaired data; paired t-test only when requested. Align pairs by subject ID, report incomplete-pair exclusions, and never duplicate technical replicates as independent observations.
- Always run non-imputed InMoose limma alongside the imputed t-test. Paired limma uses within-subject differences and >=4 complete observed pairs per feature by default, abundance-dependent moderation, `robust=False`. Unpaired limma uses the condition coefficient and optional explicitly typed covariates; require observations in both groups and positive residual df. Stop on confounding. Do not drop covariates or change thresholds to force a result.
- Preserve non-testable features with missing p-values and a reason. BH-adjust each test family separately over its finite p-values. Positive log2FC always means test minus reference.
- Explain that t-test/limma differences combine imputation, feature eligibility and statistical modeling. Neither agreement nor imputation-burden plots validate imputed-value accuracy; limma does not resolve non-random missingness.
- Preserve phosphosite identifiers and protein mappings. Optional protein adjustment is a separate parallel analysis of observed log2 site minus matched observed log2 protein abundance, followed by its own filtering/imputation; do not use imputed proteins to create observed site ratios. This is not absolute occupancy. Never infer protein mapping from an ambiguous protein group.
- Use unique mapped genes for Hallmark ORA, with the method's testable mapped genes as background. Do not count multiple sites as multiple genes. Label phosphosite Hallmark results as gene-level context, not kinase activity. Keep localization filtering explicit; do not infer a measured probability from a filename.
- Do not carry study-specific patient exclusions from the source notebooks into another dataset. Flag outliers for discussion rather than excluding automatically.

## Outputs and visual conventions

Export feature IDs as the CSV index and gene symbols as a separate column. Keep separate assay/scope/method folders, imputed matrices and masks, filtering logs, sample/group/feature missingness tables, hit audits, and effect/significance agreement summaries. Export full and top-ten Hallmark tables and contributor tables for both directions, including non-significant pathways. Always render top-ten and contributor figures, using an explanatory placeholder when no contributors exist.

Use consistent condition colors across scopes, editable vector PDF plus PNG, top 500 variable features and per-feature unit-variance scaling for PCA, with variance explained on axes. Use nominal p-value on the volcano y-axis and adjusted p-value for significance. Record exact configuration, input/GMT hashes, backend versions, feature eligibility and sample exclusions. Do not calculate PCA distances or permutations.

## Modular use

Import `read_inputs`, `filter_observed`, `impute`, `plot_pca`, `ttest`, `limma`, `enrichment`, `imputation_audit` or `adjust_phosphosites` for partial requests. Do not run unrelated stages when only one is requested. Use `scripts/test_inputs.py` for Excel/parquet import regression checks and `scripts/test_proteomics.py` for the synthetic analysis regression check; it creates temporary data and requires InMoose.
